### 1. [GHC: Expanding Residual Interfaces in Hyper-Connections](https://arxiv.org/abs/2611.31350)

arXiv · paper · architecture · arXiv:2611.31350
_Tianyu Li, Hongtao Zhang, Dongchen Han_

**In one line:** GHC splits hyper-connection branches into groups along heads/FFN channels; reports 35% training-efficiency gain over Pre-Norm

**What:** Hyper-connections widen the residual stream into several mixed streams, but each attention/FFN branch still reads and writes through a single interface. Grouped Hyper-Connections (GHC) split each branch into parallel groups along attention heads or FFN channels, so different groups get their own residual read/write interfaces, at negligible parameter and memory-access overhead. Tested on both dense and MoE models.

**Result:** Per the abstract, GHC beats Identity Hyper-Connections (IHC) and improves training efficiency by 35% over Pre-Norm and by 10% over IHC.

**Critique:** Details come from the arXiv listing abstract only (cs.LG cross-list in cs.CL). 'Training efficiency' is not defined in the abstract (tokens-to-target-loss vs. wall-clock), and model scales, token budgets and downstream evals are not stated. Wall-clock cost of the extra stream mixing is claimed negligible but not quantified. No comparison against mHC-style manifold-constrained variants is mentioned.

### 2. [Fix How It Acts, Not How It Thinks: Surgical Fine-Tuning of Frontier LLMs](https://arxiv.org/abs/2611.32064)

arXiv · paper · training · arXiv:2611.32064
_Sandeep Singh Sandha, Prann Bansal, Arvind Sundararajan_

**In one line:** Merging a BF16 fine-tune into a mixed FP8/NVFP4 release erases 93% of the update; rounding each step fixes it (+8.4 pts Terminal-Bench 2.1)

**What:** Fine-tuning a frontier model in BF16 and then merging into its low-precision release format can silently discard the update: the median weight change is only 1.5% of one quantization rounding step, so rounding back to the mixed FP8/NVFP4 release format removes most of it. Merge-aware fine-tuning rounds weights to the release format at each training step so the learned change survives quantization.

**Result:** Merging into the mixed FP8/NVFP4 release erases 93% of the BF16 update. Merge-aware fine-tuning improves Nemotron-3.5 agentic coding by up to 8.4 points on Terminal-Bench 2.1.

**Critique:** From the listing abstract only. 'Up to 8.4 points' is a best case; the average gain, the baseline it is measured against (naive merge vs. BF16 model) and run-to-run variance are not given. Single model family (Nemotron-3.5) and single headline benchmark. Comparison with standard QAT/straight-through approaches is not mentioned in the abstract.

### 3. [ModernELECTRA: Replaced-Token Detection with Boundary-Window Reconstruction for Compact Encoders that Classify and Embed](https://arxiv.org/abs/2611.31495)

arXiv · paper · efficiency · arXiv:2611.31495
_Mykhailo Shtopko, Ihor Stepanov, Dmytro Vodianytskyi_

**In one line:** ModernELECTRA trains 31M/61M encoders on ~1T tokens; its FlashDeBERTa kernel is 10x faster with 93% less memory at 4096 tokens

**What:** Adds a boundary-window reconstruction auxiliary task to ELECTRA-style replaced-token-detection pretraining and trains EdgeCoder-31M (8 layers, English) and EdgeCoder-Multilingual-61M (16 layers, 46 languages), each on about 1T tokens. Separately introduces FlashDeBERTa, a fused disentangled-attention kernel that never materializes the n x n score matrix and loads existing DeBERTa checkpoints unchanged.

**Result:** GLUE 86.0 (English) and 85.1 (multilingual). The English model beats Ettin-Enc-32m (83.5) and MiniLM-L12 (84.6) on GLUE and matches them on MTEB English v2 (51.1); the multilingual model beats the 2.3x larger mmBERT-small on GLUE. FlashDeBERTa at 4096 tokens: 10x faster and 93% less memory than the reference implementation.

**Critique:** From the listing abstract only. The kernel speedup is against the reference (unfused) DeBERTa implementation, not against other fused or FlashAttention-style variants; GPU type and batch size are not stated. No ablation of the boundary-window task's contribution is reported in the abstract. MTEB is only 'matched', not improved.

### 4. [Directly Maximizing On-policy Expected Accepted Length for Speculative Decoding](https://arxiv.org/abs/2611.31256)

arXiv · paper · inference · arXiv:2611.31256
_Ziying Zhang, Yaqing Wang, Yong Liu_

**In one line:** FreDraft trains speculative-decoding drafters on-policy to directly maximize expected accepted length rather than token-level alignment

**What:** Draft models for speculative decoding are usually trained to match the target's token distribution, a proxy for what matters (how many tokens get accepted). FreDraft trains on drafts sampled from the current draft model and directly maximizes their expected accepted length; it analytically marginalizes the token-level acceptance rate using the target's full vocabulary distribution to reduce gradient variance, and adds an explicit penalty on sampled tokens whose probability the draft overestimates.

**Result:** The abstract reports better accepted length and decoding speedup than strong baselines across multiple benchmarks and target models, plus faster on-policy training convergence, but gives no numbers.

**Critique:** No quantitative results, baseline names (e.g. EAGLE-family, DFlash) or target models are given in the abstract, so the size of the gain is unknown. Details from the listing abstract only.

### 5. [Factorized Context Attention: From Emulated to Native Grid Probing](https://arxiv.org/abs/2611.32423)

arXiv · paper · inference · arXiv:2611.32423
_Mohamed Eltahir, Manar Eyad, Yara Alzahrani_

**In one line:** Factorized Context Attention: training-free block-sparse attention reusing one KV cache; +9-14 pts on long novels over a single pass

**What:** Grid probing answers long-input questions by running the model over many spans separately, which re-encodes context repeatedly. Factorized Context Attention is a training-free block-sparse attention scheme that encodes the input once into a KV cache and then runs all spans as batched, masked sequences over that shared cache, making grid probing native rather than emulated.

**Result:** About +10 points over a single pass on long video and +9-14 points on long novels; finds needles in videos over a thousand frames and texts four times the context window; answers a later question in as little as one tenth of grid probing's time.

**Critique:** From the listing abstract only. Models, benchmarks and absolute accuracies are not named in the abstract; 'as little as a tenth' is a best case. Comparison is against single-pass and emulated grid probing, not against other long-context methods (RAG, sparse-attention retrofits, context extension).

### 6. [Byte Patches versus BPE at Matched Data: A Matched-Twin Comparison at 350M Parameters](https://arxiv.org/abs/2611.31790)

arXiv · paper · architecture · arXiv:2611.31790
_Asadullah Maliyawala, Andrej Lisal_

**In one line:** Matched 350M twins on 10B bytes: BPE-8k beats a MEGABYTE-style byte-patch model on bits/byte by 5.2%; bytes win on CharBench

**What:** Controlled comparison of tokenizer-free byte-patch modelling versus BPE: a MEGABYTE-style byte-patch Transformer (local64) and a BPE-8k Transformer, both at 350M parameters and trained on the same 10 billion bytes, evaluated on bits per byte by domain and on character-level and factual probes.

**Result:** BPE-8k has lower bits per byte: relative gaps -5.2% overall, -4.9% text, -9.3% code, -6.1% math. local64 wins CharBench 53.7% vs. 40.0%; BPE-8k wins fact200 16.5% vs. 7.0%.

### 8. [CoT-Proxy: Cross-Format Transfer for Distilling Long-Horizon Policies](https://arxiv.org/abs/2611.33148)

arXiv · paper · training · arXiv:2611.33148
_Dawid J. Kopiczko, Tijmen Blankevoort, Yuki M. Asano_

**In one line:** CoT-Proxy distills agent policies from teacher actions with an empty reasoning block; Qwen3-4B goes 7% to 48% on AppWorld

**What:** Distilling agents from teachers whose chain of thought is hidden or long is hard. The student is trained only on the teacher's actions with its own reasoning block left empty, plus a KL loss on its own generations; the behavior transfers to inference with thinking enabled ('cross-format transfer'). CoT-proxies extend this further.

**Result:** Distilling Qwen3.6-27B actions raises Qwen3-4B on AppWorld from 7% to 18% and Qwen3-32B from 12% to 25%; CoT-proxies raise Qwen3-4B to 35%. Distilling GPT-5.6 Luna from visible outputs and reasoning summaries raises Qwen3-4B from 7% to 48% on AppWorld and from 3% to 28% on SWE-bench Verified.

**Critique:** Comparisons are against the undistilled student, not against standard SFT on teacher traces or other distillation baselines (per the abstract). Distilling from a closed API model's outputs raises terms-of-service questions not addressed in the abstract. Training compute and number of trajectories not stated. From the listing abstract only.

### 9. [TableRouter: Query-Aware Evidence Construction for Long-Table Question Answering](https://arxiv.org/abs/2611.32006)

arXiv · paper · inference · arXiv:2611.32006
_Anahita Bolourani, Xiaofeng Lin, Tung Sum Thomas Kwok_

**In one line:** Training-free TableRouter picks compute vs. coverage routes for long-table QA; beats 6 baselines in 9/9 settings with 77-95% fewer FLOPs

**What:** Long tables overflow or dilute LLM context. TableRouter is a training-free, query-aware router that chooses between a computation route (computing statistics over the table) and a coverage route (constructing a compact evidence subset), instead of feeding a truncated table to the model.

**Result:** Beats the strongest of six single-call baselines in all nine settings by 1.2-18.3 accuracy points while using 77-95% fewer estimated FLOPs than truncated-table prompting. With Qwen2.5-7B: 35.8% vs. 16.4% for the strongest external baseline. Explicit computed statistics add up to 40.0 points.

**Critique:** FLOPs are 'estimated', not measured latency. Baselines are single-call methods; multi-call agentic table methods are not mentioned in the abstract. Older backbone (Qwen2.5-7B). From the listing abstract only.

### 10. [SwiftLoop: Selective Refinement for Adaptive Implicit Reasoning in Looped Transformers](https://arxiv.org/abs/2611.31481)

arXiv · paper · inference · arXiv:2611.31481
_Tianyi Zhao, Ke Wan, Chen Chen_

**In one line:** SwiftLoop freezes token positions during looped-transformer inference based on K/V reusability and output impact to cut loop compute

**What:** Looped transformers re-run the same layers several times on every position. SwiftLoop applies position-wise freezing during looped inference: positions whose keys/values are reusable and whose further refinement has little effect on the output stop being updated, so later loop iterations only refine a subset of positions.

**Result:** The abstract reports favorable accuracy-compute trade-offs versus fixed-loop inference and adaptive baselines, with measured inference acceleration, but gives no numbers.

**Critique:** No quantitative speedup, accuracy or model sizes in the abstract, and the adaptive baselines are not named. Relevant given recent loop-transformer production claims (e.g. GLM-5.4), but tested scale is unknown. From the listing abstract only.
